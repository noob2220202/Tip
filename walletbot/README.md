# walletbot — 지갑 입금 알림·시세·에너지 임대 봇

TRON 지갑(사용자당 최대 3개)에 **USDT(TRC20)·TRX가 입금되면 알려 주고**, 잔액을 원화로 환산해 보여 주고, 빗썸 USDT 시세와 **김프**를 조회·알림하는 봇입니다. USDT 전송 수수료를 아끼는 **TRON 에너지 임대**를 원가에 팔고, **텔레그램 비즈니스**로 연결하면 주인의 DM 대화창에서 `/조회` `/시세` `/환율`에 답합니다. 여러 사용자가 같이 쓰는 일반 봇이고, 채널 가입 게이트는 공통 `run_bot`이 붙입니다.

## 기능

| 기능 | 설명 |
| --- | --- |
| 💼 지갑 | TRON 주소(체크섬 검증)를 3개까지 등록. 별명, 삭제 가능. 등록한 시점 이후 입금만 알린다 |
| 📥 입금 알림 | USDT, TRX 입금을 **블록에 들어간 직후(약 3~6초)** 에 한 번 알린다. 보낸 주소·금액(+원화)·시각(KST)·TRONSCAN 링크. 실패한 거래는 알리지 않는다 |
| 🧹 소액 필터 | 최소 알림 금액(USDT·TRX 따로, 기본 0.1). 주소 위장용 소액 스팸 입금을 거른다. 1 미만 입금에는 경고를 붙인다 |
| 💰 잔액 | 지갑별·합계 USDT, TRX와 빗썸 시세 기준 원화 환산 |
| 📈 시세 | 빗썸 USDT/KRW·TRX/KRW, 기준 환율(USD/KRW), 김프(%) |
| 📉 김프 조건 | "N% 이상/이하가 되면 알림". 최대 3개. 한 번 울린 뒤 0.2%p 되돌아가야 다시 울린다 |
| 🕘 정기 시세 | 정한 시각(KST, 최대 3개)에 시세 전송. 정한 시각에서 10분 안이면 늦게라도 보낸다 |
| ⚡ 에너지 임대 | USDT를 보낼 지갑에 1시간 에너지를 빌려 준다. 공급처 세 곳 중 가장 싼 원가 + 마진(기본 0). 아래 "에너지 임대" |
| 🔎 /조회 | 주소의 USDT·TRX 잔액(원화), 활성화 여부, 지금 쓸 수 있는 에너지·대역폭 |
| 💱 /환율 | `/환율` 기준 환율·USDT·TRX 시세, `/환율 100`(USDT), `/환율 10만원`, `/환율 50trx`, `/환율 $20` 바로 환산 |
| 🤝 비즈니스 | 텔레그램 비즈니스로 연결하면 주인의 DM 대화창에서 `/조회` `/시세` `/환율`. 아래 "비즈니스 연결" |

명령어: `/지갑` `/잔액` `/시세` `/알림` `/설정` `/에너지` `/조회` `/환율`, 영문 `/wallet` `/balance` `/price` `/alerts` `/energy` `/check` `/rate` `/business`, `/menu` `/help` `/cancel`. 텔레그램 명령어 메뉴에는 영문만 등록할 수 있어서 한글 명령어는 직접 입력한다. 모든 기능은 버튼으로도 쓸 수 있다.

## 에너지 임대

USDT(TRC20)를 보낼 때 보내는 지갑에 에너지가 없으면 TRX가 탄다(2026-10 기준 받는 쪽에 USDT가 있으면 약 6.4 TRX, 없으면 약 13 TRX). 에너지를 1시간 빌려 두면 그 수수료가 공급처 원가(약 1~2 TRX)로 줄어든다.

**흐름**
1. ⚡ 에너지 임대 → **에너지 사기** → USDT를 보낼 **내 지갑 주소**(등록 지갑 버튼으로도 고를 수 있다). 활성화 안 된 지갑·컨트랙트·결제 주소는 받지 않는다.
2. **받는 주소**를 보내면 그 주소로 USDT 전송을 모의 실행(`triggerconstantcontract`)해서 필요한 에너지를 정확히 잰다. 모르면 "USDT 있음 / 없음·모름" 버튼(없음은 두 배로 넉넉하게). 이미 에너지가 충분하면 주문하지 않는다.
3. 견적: 필요한 에너지(+500 여유, 1,000 단위 올림, 최소 65,000), 가격, 태울 때 비용과 절약률. 2분이 지나면 다시 계산한다.
4. 주문: **정확한 TRX 금액**과 결제 주소(따로 보내 복사하기 쉽게)를 안내한다. 기한 기본 10분.
5. 입금은 블록 스캔으로 3~6초 안에 잡는다(결제 주소를 스캔 대상에 더한다). 30초마다 결제 주소 내역도 훑어 놓친 입금을 메운다.
6. 가장 싼 공급처에 1시간 에너지를 주문하고, **체인에서 받는 지갑의 에너지가 필요한 양 이상인 것을 확인한 뒤** "✅ 에너지 도착, 지금 보내셔도 됩니다"를 보낸다.

**가격**: 공급처마다 1시간 원가(sun/에너지)를 묻고(30~90초 기억) 가장 싼 값 × 에너지 + `ENERGY_MARGIN_TRX`를 0.001 TRX 단위로 올린다. 마진 0이면 소개·견적에 "원가 그대로"를 표시한다.

**입금 구분**: 주문마다 금액 끝자리를 0.001 TRX씩 다르게 배정해서(최대 +0.099) 금액만으로 주문을 찾는다. 메모는 1 TRX 수수료가 붙어서 쓰지 않는다. 보내는 주소를 묻지 않으므로 거래소에서 출금해도 된다(에너지는 주문 때 입력한 지갑으로 간다). 열린 주문과, 만료·취소 후 30분 안의 주문 금액은 다른 주문에 배정하지 않는다.

| 입금 | 처리 |
| --- | --- |
| 정확한 금액, 기한 안 | 처리 |
| 정확한 금액, 만료·취소 뒤 30분 안 | 그대로 처리(거래소 출금 지연 등) |
| 금액이 다른데 보낸 주소가 주문 지갑 | 손님과 관리자에게 알림(수동 환불) |
| USDT 입금, 맞는 주문이 없는 TRX | 관리자에게 알림 |
| 0.5 TRX 미만 | 스팸으로 보고 무시 |

**중복 구매 방지** (돈이 걸린 부분)
- `paid → ordering`으로 먼저 바꾼 뒤에만 공급처를 부른다. 공급처 주문 번호는 `e{주문 id}`로 고정한다.
- **거절**(주문이 안 만들어짐: 잔고 부족, 형식 오류, 공급처 장애 응답)이면 다음으로 싼 공급처로 넘어간다. 잔고 부족이면 관리자에게 알린다.
- **불확실**(시간 초과, 5xx, 이상한 응답)이면 **다른 공급처로 넘기지 않는다.**
  - Netts·CatFee는 같은 번호의 재요청이 새 주문을 만들지 않으므로(Netts `X-Idempotency-Key`, CatFee `client_order_id`) 20초 뒤 같은 번호로만 다시 묻는다. 6번 넘게 불확실하면 관리자 확인.
  - trxx는 문서에 중복 방지가 없어서 **다시 보내지 않고** 2분 동안 체인에서 에너지가 들어오는지만 본다. 안 보이면 관리자 확인.
  - 같은 번호로 다시 물었는데 거절이 오면(처음 요청이 접수됐을 수 있으므로) 거절이 아니라 불확실로 본다.
- 재시작하면 공급처를 부르던 주문은 같은 공급처에 같은 번호로 다시 묻는다(trxx는 체인 확인만).
- 원가가 받은 금액보다 `ENERGY_MAX_LOSS_TRX`(기본 1) 넘게 비싼 공급처만 남으면 주문하지 않고 실패로 넘긴다(관리자 환불).
- 공급처가 성공이라고 해도 2분 안에 체인에서 에너지가 안 보이면 "USDT는 아직 보내지 마십시오"와 함께 관리자 확인으로 넘긴다.
- 서버에는 결제 지갑 개인키가 없다. 환불(실패·금액 불일치·USDT 입금)은 관리자가 지갑에서 직접 보내고 `/energy_done 주문번호 메모`로 정리한다.

**공급처** (2026-10 조사, 1시간 65k 기준 원가 약 1.03~1.3 TRX)

| 공급처 | 인증 | 주문 | 중복 방지 | 비고 |
| --- | --- | --- | --- | --- |
| Netts | `X-API-KEY` + 화이트리스트 IP(`X-Real-IP`) | `POST /apiv2/order1h` | `X-Idempotency-Key`(HMAC, 24시간) | 서버 공인 IP를 Netts에 등록해야 한다. 가격 조회는 분당 1회 |
| CatFee | HMAC-SHA256 Base64(시각+메서드+경로?쿼리) | `POST /v1/order?…&client_order_id&activate=false` | `client_order_id` | 시간대별 가격(16~28 sun) |
| trxx | HMAC-SHA256 hex(시각&정렬 JSON) | `POST /api/v1/frontend/order` | 문서에 없음 → 재요청 안 함 | 가장 싼 경우가 많다. 운영사·환불 규정 미확인 → 잔고를 적게 둔다 |

키가 있는 공급처만 쓴다. 공급처마다 TRX를 미리 충전해 두어야 하고, 10분마다 잔고를 확인해 `ENERGY_LOW_BALANCE_TRX`보다 적으면 알린다(6시간에 한 번).

**관리자**: `/energy_admin`(최근 24시간 주문 수·매출·원가, 공급처 잔고, 확인 필요 주문), `/energy_done 주문번호 메모`(실패·확인 필요 주문을 처리됨으로).

**법적 주의**: 충전식 잔액이나 USDT↔TRX 교환은 특금법상 가상자산사업자 신고 대상일 수 있어 넣지 않았다. 에너지 재판매만으로도 해당하는지는 불분명하다.

## 비즈니스 연결

주인이 텔레그램 **설정 → 텔레그램 비즈니스 → 챗봇**에서 이 봇을 연결하면, 주인이 다른 사람과 나누는 **DM 대화창**에서 명령에 답한다(그룹은 텔레그램이 지원하지 않는다). 2026-05부터 프리미엄이 없어도 연결할 수 있다.

- `/조회 T주소` · 주소가 담긴 메시지에 답장하며 `/조회` · 그냥 `/조회`(그 대화에 마지막으로 나온 주소)
- `/시세`, `/환율 100`, `/환율 10만원`
- **주인이 직접 입력한 명령에만 답한다.** 상대가 입력하면 무시한다(답장이 주인 이름으로 나가므로). 봇이 대신 보낸 메시지·자동 응답은 무시한다.
- 주인 한 명당 1분에 20번까지. 텔레그램 규칙상 상대가 24시간 안에 말을 건 대화에만 답할 수 있다.
- **대화 내용은 저장하지 않는다.** 대화마다 마지막 지갑 주소 하나만 메모리에 두고(최대 5,000개 대화, 재시작하면 잊는다), DB에는 연결 정보(주인·권한)만 남긴다.
- 채널 구독은 **주인** 기준으로 확인한다. 미가입이면 대화창에는 아무것도 보내지 않고 주인에게 봇 대화로 안내한다(1시간에 한 번).
- 연결·해제·권한 변경은 주인에게 봇 대화로 알린다. 대화창의 "봇 관리" 버튼(`/start bizChat…`)을 누르면 연결 안내를 보여 준다.
- **운영자 설정**: BotFather → 봇 → Bot Settings → **Secretary Mode**(예전 이름 Business Mode)를 켜야 연결할 수 있다.

## 시세 출처

- **빗썸**: `GET /v1/ticker?markets=KRW-USDT,KRW-TRX`
- **기준 환율**: 무료 환율 API(`open.er-api.com`)의 USD/KRW. 구글에는 공식 API가 없어서 이쪽을 쓴다.
- **김프** = 빗썸 USDT 가격 ÷ 기준 환율 − 1. USDT 1개를 1달러로 계산하므로 실제 USDT/USD 시세와는 소수점 차이가 날 수 있다.
- 시세는 10초 캐시한다. 빗썸 조회가 실패하면 10분 안의 마지막 값을 "조회 지연"으로 표시하고, 환율만 실패하면 시세는 보여주되 김프는 계산하지 않는다.

## 입금 감지 방식 (블록 스캔)

지갑마다 TronGrid에 묻지 않고, **새 블록을 3초마다 받아서 봇이 직접 걸러냅니다.** 호출 수가 지갑 수와 상관없이 하루 약 3만 번으로 일정해서 지갑이 수백 개여도 무료 한도(하루 약 10만)에 들어갑니다.

- 블록 안에서 TRX는 일반 전송(`TransferContract`), USDT는 USDT 컨트랙트의 `transfer` / `transferFrom` 호출 데이터를 읽는다. 실패한 거래와 위조 토큰은 무시한다.
- **알림은 입금이 블록에 들어간 직후(약 3~6초)에 한 번만** 보낸다. "확정 대기" 같은 상태 표시도, 메시지 수정도 없다. 실패한 거래(`contractRet`가 SUCCESS가 아닌 것)는 처음부터 걸러서 알리지 않는다. TRON은 블록이 뒤집히는 일이 매우 드물어서 확정을 기다리지 않는다.
- 읽은 블록 번호를 DB에 저장해서, 재시작하면 꺼져 있던 동안의 블록을 이어서 훑는다. 같은 입금은 `notified` 표로 막아서 두 번 알리지 않는다.
- 스캔이 15분 넘게 밀리면(오래 꺼졌거나 TronGrid 장애) 블록을 하나씩 따라잡지 않고, 지갑별 내역 조회로 놓친 입금을 메운 뒤 최신 블록으로 건너뛴다.
- **잔액 대조**: 일괄 전송 컨트랙트처럼 블록의 호출 데이터에 드러나지 않는 입금은 스캔이 못 잡는다. 그래서 `RECONCILE_MINUTES`(기본 30분)마다 주소별로 잔액을 확인해서 **늘어난 주소만** 내역을 조회해 늦게라도 알린다.
- 블록 스캔은 TronGrid 한 곳에 의존한다. 429나 장애가 나면 관리자에게 알리고(30분에 한 번) 쉬었다가 이어서 한다.

## 동작 규칙

- 같은 주소를 여러 사람이 등록해도 감시는 한 번만 한다.
- 봇을 막은 사용자는 비활성 처리해서 알림·감시 대상에서 뺀다. `/start`를 다시 보내면 되살아난다.
- 알림 전송이 일시적으로 실패하면 기록을 지워, 잔액 대조 때 다시 알린다.
- 지갑을 등록하기 전에 블록에 들어간 입금은 알리지 않는다.

## 운영 한도와 비용

| 항목 | 값 |
| --- | --- |
| 블록 스캔 | 하루 약 28,800~37,000 요청 (지갑 수와 무관) |
| 잔액 대조 | 지갑 수 × (1,440 ÷ `RECONCILE_MINUTES`) 요청/일. 500개·30분이면 약 24,000 |
| 데이터 | 블록 하나가 압축 전 약 450KB. gzip을 받으면 약 95KB(하루 약 2.7GB). TronGrid가 gzip을 내려주는 것을 확인했다(블록 하나 약 93KB) |
| CPU | 블록 하나 해석 약 3.5ms → 코어 1개의 약 0.1% |

지갑이 1,000개를 넘으면 `RECONCILE_MINUTES=60`으로 늘려 호출을 줄인다. 상한은 `MAX_WALLETS_TOTAL`(기본 500)이다.

| `ADMIN_IDS` | 관리자 ID. 오류 알림을 받는다 |
| `TRONGRID_API_KEY` | TronGrid 키 (없어도 되지만 한도가 매우 낮다) |
| `MAX_WALLETS_TOTAL` | 서버 전체 주소 상한. 기본 500 |
| `RECONCILE_MINUTES` | 잔액 대조 간격(분). 기본 30, 최소 5 |
| `BITHUMB_URL`, `FX_URL` | 시세 출처 주소(기본값 사용 권장) |
| `VERIFY_SECRET` | 채널 가입 검수 비밀값 |
| `ENERGY_PAY_ADDRESS` | 에너지 결제를 받을 관리자 지갑 주소(조회만 한다). 비우면 에너지 임대를 끈다 |
| `ENERGY_MARGIN_TRX` | 주문당 마진(TRX). 기본 0 = 원가 판매 |
| `ENERGY_MAX_LOSS_TRX` | 원가가 받은 금액보다 이만큼 넘게 비싸면 주문하지 않는다. 기본 1 |
| `ENERGY_ORDER_MINUTES` | 입금 기한(분). 기본 10 |
| `ENERGY_LOW_BALANCE_TRX` | 공급처 잔고 부족 알림 기준. 기본 50 |
| `NETTS_API_KEY`, `NETTS_REAL_IP` | Netts 키와, Netts 화이트리스트에 등록한 서버 공인 IP |
| `CATFEE_API_KEY`, `CATFEE_API_SECRET` | CatFee 키·시크릿 |
| `TRXX_API_KEY`, `TRXX_API_SECRET` | trxx 키·시크릿 |

에너지 임대를 켜려면: 결제 받을 지갑 주소를 정하고 → 공급처(1곳 이상)에 가입해 키를 받고 TRX를 충전 → `.env`를 채우고 재시작. 시작 로그에 `에너지 임대 켜짐: 공급처 …`가 보이면 된다. 비즈니스 연결은 BotFather에서 Secretary Mode만 켜면 된다.

배포는 `bash /root/Tip/scripts/deploy.sh`.
