# giveaway — 기프트콘 이벤트 봇

채널을 구독 중인 봇 사용자에게 **추첨으로 기프트콘을 보내거나**, **모두에게 같은 기프트콘을 보내는(선착순 사용)** 봇입니다. 이벤트는 관리자(`ADMIN_IDS`)만 만들고 실행합니다.

## 대상(참가 자격)

- 봇에 `/start`를 보낸 사람(봇을 차단하지 않은 사람) 중 **지금 필수 채널을 구독 중인 사람**.
- 구독 여부는 **실행할 때 한 명씩 다시 확인**한다. `shared/config/common.toml`의 필수 채널과 `verify` 서비스를 그대로 쓴다. 채널을 나간 사람은 빠진다.
- 관리자 계정은 대상에서 빠진다.

## 관리자 사용법 (봇에서 `/start` → 버튼, 또는 `/giveaway`)

1. **➕ 새 이벤트** → 방식 선택
   - **🎲 추첨**: 당첨 인원 N을 정하고 기프트콘을 N개 이상 등록(이미지는 한 장씩, 텍스트 코드는 한 줄에 하나씩). 남는 것은 예비로 쓴다.
   - **🎁 전원 동일**: 기프트콘 1개(이미지 또는 텍스트)를 등록. 메시지에 "선착순으로 먼저 사용하신 분이 사용권" 안내가 붙는다.
2. 제목과 (선택) 당첨자에게 함께 보낼 안내 문구를 정한다.
3. 이벤트 화면에서 **👀 나에게 미리보기**(코드를 소진하지 않는다) → **▶️ 지금 실행**.
4. 진행 상황이 대화로 오고, 끝나면 받은 사람 목록과 집계가 온다. `/giveaways`로 지난 이벤트를 본다.
5. 끝난 이벤트는 **🧹 코드·이미지 지우기**로 DB에서 코드를 지울 수 있다(누가 받았는지 기록은 남는다).

## 코드가 겹치지 않게 (한 번만 쓰는 코드라서)

- 코드를 **배정하는 기록을 DB에 먼저 남기고** 보낸다. 같은 코드가 두 사람에게 갈 수 없다.
- **확실히 못 보낸 경우**(봇 차단, 계정 없음)에만 코드를 되돌려 다음 사람에게 준다.
- **보내졌는지 알 수 없는 경우**(네트워크·서버 오류, 보내던 도중 재시작)는 코드를 되돌리지 않고 `확인 필요`로 남기고 관리자에게 알린다. 중복 지급보다 안전하다.
- 같은 이벤트는 한 번만 실행된다(상태가 `draft/paused → running`으로 바뀌는 건 한 번뿐). 한 사람이 같은 이벤트에서 두 번 받지 않는다.
- 이미지가 잘못됐거나 텔레그램 요청 제한이 풀리지 않으면 **일시 중지**하고, 원인을 고친 뒤 **이어서 실행**하면 이미 보낸 사람은 건너뛰고 이어간다. 구독 확인이 5번 연달아 실패해도(검수 봇 장애 등) 같은 방식으로 멈춘다.
- 봇이 재시작되면 진행 중이던 이벤트를 이어서 한다.

## 규모

구독 확인이 한 명당 1번의 호출이고 초당 약 20건(`SEND_PER_SEC`)으로 보낸다. 대상이 1만 명이면 전원 발송은 약 10~15분 걸린다. 추첨은 무작위로 한 명씩 확인하다가 N명이 차면 끝나서 대상이 많아도 빠르다.

## 설치

```bash
cd /root/giveaway && cp .env.example .env && nano .env
```

| 변수 | 설명 |
| --- | --- |
| `BOT_TOKEN` | BotFather 토큰 |
| `ADMIN_IDS` | 이벤트를 만들고 실행할 수 있는 계정 |
| `VERIFY_SECRET` | verify/.env의 값과 같게 |
| `SEND_PER_SEC` | 초당 발송 건수(기본 20) |

기프트콘 코드는 `data/bot.db`에 평문으로 저장된다. DB 파일을 서버 밖으로 내보내지 않게 관리하고, 끝난 이벤트는 코드를 지운다. 배포는 `bash /root/Tip/scripts/deploy.sh`.

## 테스트

```bash
cd giveaway && python3 -m pytest
```
가짜 Bot API와 가짜 구독 확인으로 이벤트 만들기 흐름과 입력 검증, 추첨(구독자만·중복 없음·무작위·차단자 건너뛰기와 코드 되돌리기·불확실한 전송은 코드 재사용 금지·대상 부족 보고), 중복 실행 방지, 재시작 이어받기, 전원 동일 발송, 일시 중지와 이어서 실행, 취소·코드 지우기, 관리자 전용 권한, `verify` 서비스와 직접 확인 두 가지 구독 확인을 검증한다.
