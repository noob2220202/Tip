# boost

텔레그램 **그룹·채널 부스트**를 판매하는 봇입니다. 결제는 USDT(TRC20)이고, 입금이 확인되면 SMM 패널에 자동으로 주문합니다. 구독 게이트·사용자 DB·관리자·브로드캐스트는 `../shared`를 씁니다.

## 흐름

1. 사용자가 상품을 고르고, 부스트를 올릴 **그룹·채널 링크**와 **본인의 보내는 TRC20 주소**를 입력합니다.
2. 봇이 입금 지갑과 **정확한 금액**, 마감 시간(기본 30분)을 안내합니다.
3. 봇이 TronGrid를 15초마다 조회해, 아래 조건을 **모두** 만족하는 입금을 승인합니다.
   - 보낸 주소 = 사용자가 입력한 주소
   - 받는 지갑 = `WALLET_ADDRESS`, 토큰 = USDT 컨트랙트, 블록 확정(`only_confirmed`)
   - 금액이 주문 금액과 **정확히** 일치
   - 블록 시간이 주문 생성 ~ 마감 사이
   - 처음 보는 txid (txid는 DB에서 UNIQUE)
4. 승인되면 SMM 패널 `action=add`로 주문하고, `action=status`로 완료를 추적해 사용자에게 알립니다.

같은 금액을 보낸 서로 다른 사용자는 **보내는 주소**로 구분됩니다. 같은 주소·같은 금액의 주문이 둘이면 먼저 만든 주문부터 맞춥니다.

## 주문 상태

`awaiting_payment` → `paid` → `submitting` → `processing` → `completed`
그 밖에 `expired`, `cancelled`, `manual_review`(관리자 확인 필요)가 있습니다.

자동 처리하지 않고 `manual_review`로 두는 경우 (관리자에게 알림):

| 상황 | 이유 |
|---|---|
| 마감 후/취소 후 정확한 금액이 입금됨 | 돈은 들어왔으니 사람이 판단 |
| 금액이 다른 입금 (주소는 일치) | 부족/초과 입금은 자동 승인하지 않음 |
| 패널이 3번 거절 (잔액 부족 등) | 충전 후 `/retry` |
| 패널 응답이 불확실 (시간 초과 등) | 주문이 들어갔는지 모르므로 **절대 다시 보내지 않음** |
| 패널 접수 도중 봇이 재시작됨 | 위와 같음 |
| 패널에서 취소·환불·부분 완료 | 환불/재처리 필요 |

## 설정

`cp .env.example .env` 후 채웁니다.

| 변수 | 설명 |
|---|---|
| `BOT_TOKEN`, `ADMIN_IDS` | 봇 토큰, 관리자 ID |
| `WALLET_ADDRESS` | 입금받을 TRON 지갑 (체크섬 검증) |
| `TRONGRID_API_KEY` | trongrid.io에서 발급 (키 없이도 되지만 한도가 낮음) |
| `SMM_API_URL`, `SMM_API_KEY` | 패널의 API 주소와 키 (표준 API v2) |
| `ORDER_TTL_MIN`, `POLL_SECONDS` | 입금 제한 시간(분), 조회 주기(초) |
| `VERIFY_SECRET` | `verify/.env`와 같은 값 |

**상품은 `config/products.toml`에서 관리합니다.** 서비스 ID가 `0`인 상품은 판매 목록에 나오지 않으므로, 패널의 실제 서비스 ID와 가격을 넣은 뒤 `pm2 restart boost` 하세요.

## 관리자 명령

`/list [상태]` 주문 목록 · `/order 번호` 상세 · `/approve 번호` 수동 승인 · `/reject 번호` 취소(환불은 직접 송금) · `/retry 번호` 패널 재접수 · `/balance` 패널 잔액 · `/sales` 매출 · `/stats` · `/broadcast`

`/approve`는 패널 접수 여부가 불확실했던 주문이라면, **패널에서 그 주문이 없는 것을 확인한 뒤에만** 쓰세요. 중복 주문이 나갑니다.

## 10레벨 계산기

`/calc` 또는 메뉴 버튼. 구독자 수와 현재 부스트 수를 받아 목표 레벨(기본 10)까지 **추가로 필요한 부스트**와 **가장 싼 상품 조합**을 보여줍니다.

필요 개수 = `(구독자 // 250 + 1)` × 레벨 배율 (1~8레벨은 레벨÷2 올림, 9레벨은 7, 10레벨 이상은 레벨 그대로). 이 공식은 텔레그램 공식 문서가 아니라 서드파티 정리 기준이며 그룹에도 같은 식을 씁니다. 텔레그램이 규칙을 바꾸면 `products.toml`의 `[levels]`를 고치세요. 사용자 안내문에도 "채널의 부스트 화면 수치가 우선"이라고 적혀 있습니다.
